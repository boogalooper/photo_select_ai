# Photo Select AI — Windows v0.5.2 Portrait + Groups

Локальная программа для research/evaluation. Доступны **два режима**:

- **Portrait** — обычный RED по серии или опционально один лучший RED на ребёнка + YELLOW для явно отличающихся поз.
- **Group** — один главный групповой кадр → **RED**, плюс до **3** дополнительных кандидатов для ручной перестановки голов → **YELLOW**.



## v0.5.2 — один ребёнок, несколько явно разных поз

В Portrait на первом экране появился явный режим выбора **«Один ребёнок / разные позы — лучший RED + позы YELLOW»**. По умолчанию остаётся обычный режим, поэтому старое поведение не меняется.

В новом режиме программа сначала выполняет обычное разделение DBSCAN/sequential и страховку границ. Затем близкие серии одной identity могут быть связаны по нескольким ArcFace embeddings. Это не склеивает исходные серии и не меняет найденные границы детей.

Главное отличие от раннего прототипа: **RED выбирается один раз как самый лучший кадр вообще среди всех кадров связанного ребёнка**, а не как первый удачный кадр. После этого YELLOW ищутся по позам внутри всех кадров ребёнка — даже если несколько поз остались внутри одной портретной identity-серии.

Отдельная поза создаётся консервативно. По умолчанию требуется минимум **2 кадра** с поддержкой позы. Сильный поворот головы (примерно `20° yaw` или `16° pitch`) достаточен; более слабое изменение может считаться позой только вместе с заметным изменением композиции. Один только зум/перекадрирование YELLOW не создаёт. Небольшие движения головы, мимики и положения лица намеренно объединяются в одну позу. Максимум — 3 YELLOW на ребёнка.

Оценка позы использует уже имеющиеся 106 landmarks InsightFace и положение/размер лица в кадре, поэтому отдельная нейросеть и повторный GPU-анализ не нужны. Важно: это **не full-body pose estimation** — если ребёнок сильно меняет руки/корпус, но лицо остаётся практически в том же положении и направлении, такая разница может быть намеренно не распознана. Это сделано в пользу меньшего числа ложных YELLOW.

Технические пороги находятся в `Расширенные → Портреты — серии → Повторные позы одного ребёнка`; пока обычный режим выбран, они заблокированы. В журнале появляются `PORTRAIT CHILD RED`, `PORTRAIT POSE DISTINCT`, `PORTRAIT POSE SAME`, `PORTRAIT POSE REJECT` и `PORTRAIT POSE YELLOW`.

## v0.5.1 — безопасная VRAM при параллельном InsightFace

По реальному прогону на RTX 5090 32 ГБ стало видно, что четыре независимые InsightFace/ONNX Runtime CUDA-сессии во время финальной Group-проверки взгляда могут занять почти всю VRAM. В этой версии добавлен отдельный безопасный режим памяти.

- **Безопасное управление VRAM** включено по умолчанию. CUDAExecutionProvider получает ограничение `gpu_mem_limit` на каждую InsightFace-сессию и `arena_extend_strategy=kSameAsRequested`, чтобы ORT не расширял memory arena большими степенями двойки.
- Рекомендуемый бюджет — **6 ГБ на один InsightFace-worker**. Внутри него работают три ORT CUDA-модели (detector/recognition/landmarks), поэтому программа делит этот бюджет между тремя `gpu_mem_limit`. Это не абсолютный лимит всего CUDA-процесса, но не позволяет отдельной ORT arena разрастись до всей VRAM.
- Выбранные пользователем 2–4 GPU-сессии по-прежнему могут использоваться на **основном проходе по всей съёмке**. Безопасный режим отдельно ограничивает тяжёлые повторные Group-этапы `high-res/взгляд` до **2 сессий** по умолчанию.
- Для стандартного shortlist взгляда из 3 кадров программа больше не держит бессмысленную четвёртую модель: число gaze-сессий дополнительно ограничивается количеством реально анализируемых кандидатов.
- Отдельный пул финальной проверки взгляда по умолчанию пересоздаётся каждые **8 групп**. Это освобождает накопленный CUDA/ORT-кэш и не даёт ему жить всю съёмку. Значение `0` отключает периодический recycle.
- `InsightFaceAnalyzer.close()` теперь явно разрывает ссылки `FaceAnalysis.models`/`det_model`, после чего запускается GC. Это делает освобождение ORT-сессий на границах стадий более детерминированным.
- В `Расширенные → Общие / GPU → Защита видеопамяти` доступны бюджет CUDA arena на один InsightFace-worker, лимит secondary Group-сессий и период recycle. Отключение safe mode возвращает старое поведение без этих ограничений.

Для RTX 5090 32 ГБ рекомендуется: основной параллелизм `4`, безопасное управление VRAM `вкл`, `6 ГБ/worker`, secondary Group `2`, recycle `8`.

## v0.5.0 — последовательный прогресс в Group

- Прогресс-бар теперь монотонный: никакой поздний callback не может уменьшить уже показанный процент. Дополнительная защита есть и в pipeline, и в GUI.
- Этап `Разделение физических групп` больше не обновляется только раз на временной блок. Во время проверки состава показывается прогресс по внутренним границам кадров, поэтому большой временной блок больше не выглядит как зависание.
- Этап склейки фрагментов одной физической группы получил собственный прогресс по соседним блокам.
- После склейки отдельно показывается проверка найденных групп, а перед загрузкой high-res/модели взгляда статус явно сообщает, что именно сейчас загружается.
- Процент в интерфейсе показывается с точностью до 0.1%, чтобы движение было видно даже на коротких этапах, занимающих несколько процентов общей шкалы.
- Диапазоны Group теперь читаются как последовательные стадии: основной анализ лиц → разделение физических групп → склейка фрагментов → проверка групп → выбор RED/YELLOW/high-res/взгляд → завершение. Алгоритмы отбора и существующие пороги в этой версии не менялись.

## v0.4.9 — прокрутка расширенных настроек

- Все четыре вкладки `Расширенные` теперь имеют собственную вертикальную прокрутку. Это особенно важно для `Портреты — серии`, где параметры DBSCAN, sequential и страховки уже не помещаются даже в полностью развёрнутое окно.
- Прокрутка работает колесом мыши/тачпадом прямо над подписями, полями, Spinbox и Checkbutton, а также полосой прокрутки справа.
- Колесо над Spinbox прокручивает страницу, а не случайно меняет числовое значение параметра.
- Состояние вкладок (Portrait/Group, DBSCAN/sequential, high-res и другие контекстные блокировки) сохранено без изменений: прокрутка добавлена только на уровень интерфейса и не меняет алгоритмы анализа.

## v0.4.8 — страховка от редкого пропуска ребёнка в Portrait

В портретном режиме добавлена **опциональная быстрая проверка возможной пропущенной границы между двумя соседними детьми**. Она предназначена для редкой ситуации, когда обычный DBSCAN или sequential объединяет двух нормально снятых детей в одну серию и поэтому ставит только один RED.

- Выбранный пользователем метод (`dbscan` или `sequential`) остаётся основным и работает без изменений.
- Второй метод используется только как «разведчик»: он может предложить подозрительную внутреннюю границу, но не имеет права разделить серию сам.
- Каждое предложение проверяется по уже рассчитанным ArcFace embeddings нескольких кадров слева и справа: обе стороны должны быть внутренне устойчивы, достаточно отличаться друг от друга и стабильно лучше совпадать со своим локальным identity-центроидом.
- Одиночный плохой embedding не считается достаточным доказательством нового ребёнка.
- Повторного чтения фотографий и повторного запуска InsightFace нет, поэтому этот этап практически не должен увеличивать время обработки.
- Подтверждённая страховочная граница защищена от последующего автоматического объединения соседних серий через паузу.

В «Быстром старте» доступен флажок **«Портреты — проверять возможные пропущенные границы вторым методом»**. По умолчанию он выключен. Точные параметры находятся в `Расширенные → Портреты — серии → Страховка от редкого пропуска ребёнка`; когда функция выключена, её числовые параметры блокируются.

Рекомендуемый первый тест — оставить выбранный основной метод и профиль без изменений, включить только страховку и сравнить число RED с известным количеством реально снятых детей. В журнале строка `PORTRAIT GUARD SPLIT` показывает каждую реально восстановленную границу, а итоговая статистика отдельно выводит число предложенных и подтверждённых границ.

## v0.4.7 — производительность и более высокое окно

- Основное окно на обычном 1080p-дисплее стало выше (до 800 px), но автоматически уменьшается на экранах меньшей высоты. Это особенно заметно при переключении из Portrait в Group: нижние кнопки/настройки больше не должны уходить за край окна.
- В `Расширенные → Общие / GPU` доступна безопасная **CPU-предзагрузка изображений**. По умолчанию используются 2 потока: пока InsightFace анализирует текущий кадр, следующий JPEG/RAW уже читается, поворачивается и масштабируется.
- Добавлен **опциональный экспериментальный параллельный InsightFace-анализ**. По умолчанию он выключен. При включении программа создаёт 2–4 независимые InsightFace/ONNX Runtime сессии; каждый кадр обрабатывается только одной собственной сессией, а результаты затем возвращаются в исходный порядок.
- Параллельный режим применяется не только к основному проходу, но и к optional high-res поиску лиц и финальной проверке взгляда. Основные сессии закрываются перед high-res стадией, поэтому разные стадии не суммируют расход VRAM.
- Если дополнительная сессия не сможет создаться (например, из-за VRAM/CUDA), запуск не прерывается: программа продолжит с уже созданным меньшим числом сессий.
- Для видеокарты с 32 ГБ VRAM рекомендуется начать с **2 InsightFace-сессий**. 3–4 стоит пробовать только после сравнения реального времени: одна сессия уже может почти полностью загружать GPU, и тогда дополнительная параллельность не даст выигрыша.

## v0.4.6 — экспериментальная проверка взгляда в камеру

В групповом режиме появился отдельный **опциональный** критерий «Взгляд в камеру». Он не участвует в поиске границ групп и не заменяет проверку открытых глаз. Сначала обычный алгоритм формирует stable roster и ранжирует все дубли как раньше; затем только несколько лучших кадров (по умолчанию 3) перечитываются в более крупном preview и получают финальную оценку внимания к камере.

Оценка сочетает два мягких признака из уже используемого InsightFace/изображения:

- насколько фронтально расположена голова по геометрии 106 landmarks;
- где находится тёмный центр радужки/зрачка внутри контура глаза.

Это **не отдельная обученная gaze-модель**, поэтому функция помечена экспериментальной. Если глаз слишком мал, закрыт, имеет слабый локальный контраст или измерение нестабильно, состояние считается `unknown` и не штрафует кадр. Благодаря этому сомнительная оценка маленького лица не должна переворачивать выбор RED.

По умолчанию функция выключена. В «Быстром старте» включается флажком:

`Учитывать взгляд в камеру — финальная проверка лучших дублей (экспериментально)`

В «Расширенные → Группы — лица» при включении становятся доступны параметры: число проверяемых лучших дублей, размер финального preview, detector size, минимальная ширина глаза в пикселях и сила штрафа за уверенно отведённый взгляд. Когда флажок выключен, эти элементы управления блокируются.

Если одновременно включён high-res поиск пропущенных лиц, финальная проверка взгляда повторно использует уже загруженный InsightFace-анализатор, чтобы не держать два комплекта моделей в VRAM. При выключенном face-rescue создаётся отдельный анализатор только на время финальной проверки нескольких лучших кадров.

В журнале для групповых кадров добавлены поля `look_known`, `look_away`, `look_mean`. `look_known` — число людей, для которых оценка достаточно надёжна; `look_away` — сколько из них уверенно смотрят не в камеру; `look_mean` — средняя мягкая оценка направления взгляда.

Рекомендуемый первый тест: включить только «Взгляд в камеру», оставить `3` лучших дубля, preview `4800`, detector `1280`, минимум глаза `14 px`, штраф `0.45`, а high-res поиск пропущенных лиц оставить в том состоянии, в котором вы обычно его используете.

## v0.4.5 — контекстный интерфейс и независимые методы портретных серий

- **DBSCAN и sequential оставлены как равноправные методы.** Метод теперь выбирается отдельно от профиля параметров, поэтому доступны комбинации вроде `Сбалансированный + dbscan` и `Сбалансированный + sequential`. Выбор профиля больше не переключает алгоритм скрыто.
- В «Быстром старте» метод портретного разделения виден отдельным полем.
- В расширенных настройках вкладки, не относящиеся к текущему режиму, остаются видимыми для ориентира, но становятся недоступными: в Portrait отключается «Группы — лица», в Group — обе портретные вкладки. «Общие / GPU» всегда доступна.
- На вкладке «Портреты — серии» параметры разделены на три явных блока: **только sequential**, **только DBSCAN**, **общие для обоих методов**. Неактивный блок автоматически становится серым.
- Для sequential впервые вынесены в GUI его реальные параметры: порог сходства личности (`0.42`) и число кадров для подтверждения смены ребёнка (`2`).
- В группах параметры high-res становятся доступными только после включения дополнительного high-res прохода.
- `YELLOW мин/макс` блокируются, если выключен поиск резервных YELLOW.
- `Custom RED` доступен только при схеме `custom`; `Custom YELLOW` — только в Group + `custom`. В Portrait YELLOW явно считается неиспользуемым.
- Проверка настроек перед запуском теперь также учитывает контекст: неактивные параметры другого режима/алгоритма не могут мешать запуску.

## v0.4.4 — опциональный high-res и ревизия интерфейса

- Дополнительный high-res поиск пропущенных лиц в группах теперь **выключен по умолчанию** и включается отдельным флажком «Дополнительный high-res поиск пропущенных лиц (медленнее)». Обычный быстрый проход использует только устойчивый `stable` roster.
- Настройки в GUI явно разделены по области действия: **Портреты — серии**, **Портреты — детектор**, **Группы — лица**, **Общие / GPU**. Портретные критерии выбора скрываются в групповом режиме, как и раньше.
- В расширенных групповых настройках доступны основной detector size/threshold/min face area и параметры optional high-res прохода.
- В v0.4.4 `sequential` ещё рассматривался как тестовый вариант; после реального сравнения в v0.4.5 оба метода оставлены доступными.

## v0.4.3 — stable roster + повторный high-res поиск пропущенных лиц

Проверка на реальных группах показала, что устойчивые треки (`stable`) уже очень точны: в выборке 1с/2в/3з/4а/3е/4д они совпали с фактическим количеством людей, а старый механизм `promoted` добавлял ложные лица. Поэтому v0.4.3 больше не включает одноразовые детекции в состав группы.

После того как физическая группа уже найдена основным проходом, запускается второй InsightFace-проход только для восстановления полностью пропущенных участников:

- основной поиск и границы групп остаются на прежнем профиле (`det_size=1024`, threshold `0.22`);
- второй проход использует `det_size=1536`, threshold `0.14` и допускает меньшие лица (`min_face_fraction=0.00018`);
- новый человек обязан образовать повторяющийся трек минимум на двух дублях;
- кандидат должен находиться внутри пространственной области основной группы (с допуском примерно на один нормальный шаг сетки);
- размер лица сравнивается с ближайшими участниками, поэтому мелкий человек на заднем плане не должен автоматически попадать в состав;
- совпадение с существующим identity или уже занятым пространственным местом отбрасывается как повторная детекция;
- один случайный face detection больше не может увеличить число людей.

Итоговый лог теперь содержит строку вида `GROUP ROSTER | people=34 | stable=33 | rescued=1 | primary_max_faces_frame=33 | highres_max_faces_frame=34 ...`. Это позволяет отдельно видеть точный основной состав и людей, которых действительно восстановил второй проход.

Если high-res analyzer не сможет запуститься, программа не прерывает обработку: выбор продолжается по устойчивому основному составу. Основной InsightFace analyzer освобождается перед запуском high-res, чтобы не держать два комплекта CUDA-графов в видеопамяти одновременно.


## v0.4.2 — полный состав группы для выбора RED

В групповом режиме число людей теперь означает не только устойчивые треки, найденные минимум на двух дублях. Если лицо ребёнка было уверенно найдено только на одном кадре, но оно находится внутри пространственной области уже подтверждённой группы и имеет сопоставимый размер, такой одноразовый трек восстанавливается в состав группы. Это позволяет учитывать ребёнка при выборе RED: на кадрах, где его лицо не найдено, появляется штраф `missing`, вместо полного исключения ребёнка из оценки.

Одноразовые лица вне основной группы (например, прохожие на заднем плане) не добавляются. Порог трекера также согласован с порогом группового детектора (`0.22` вместо повторной отсечки на `0.30`). В логе появилась строка `GROUP ROSTER`: `people` — итоговый состав, `stable` — устойчивые треки, `promoted` — восстановленные одноразовые лица, `max_faces_frame` — максимум пригодных обнаружений на одном дубле.

Это изменение не меняет алгоритм поиска границ физических групп из v0.4.1.

## v0.4.1 — стабильный групповой выбор на сериях дублей

Эта версия меняет не число ожидаемых групп, а саму логику группового режима. Количество физических групп заранее неизвестно и определяется по последовательности файлов и составу распознанных людей.

Основные исправления:

- **исправлена фрагментация одной группы из-за неверного порядка EXIF**: если безопасно, групповой режим восстанавливает локальный порядок по номеру файла (`IMG_4048`, `IMG_4049`, ...);
- фрагменты одной физической группы перед identity-merge теперь также сортируются по номеру файла, поэтому два соседних дубля больше не обязаны случайно оказаться соседями в EXIF-порядке, чтобы быть сравнёнными;
- отрицательная разница EXIF-времени больше не превращается молча в `0 секунд`; восстановление по номеру файла выполняется отдельно и явно логируется как `GROUP ORDER NORMALIZED`;
- короткий временной фрагмент (даже один кадр) больше не выбрасывается до попытки объединения с соседней частью той же физической группы;
- разорванные треки одного ребёнка после нескольких пропусков детектора склеиваются по ArcFace identity + положению + размеру лица, если фрагменты не пересекаются по кадрам;
- один ребёнок больше не должен ошибочно считаться двумя людьми и создавать невозможный штраф `missing`;
- оценка глаз в серии адаптируется к конкретному ребёнку после минимум трёх наблюдений вместо применения одного абсолютного порога ко всем лицам;
- едва заметное пересечение порога глаз больше не имеет такого же веса, как явное моргание: используется непрерывный дефицит и отдельный сильный штраф за очевидный blink;
- слишком маленькие или слабые групповые лица не дают уверенный `closed eyes`: fine-state landmarks переводятся в состояние `unknown`, при этом identity остаётся доступным;
- тест числа групп больше не зашит только на 44: проверяются разные количества последовательных физических групп;
- в `logs/photo_select_ai.log` пишется диагностическая строка для каждого группового кадра (`visible`, `eyes_known`, `eyes_below`, `severe_blinks`, `eye_deficit`, score), а также найденные границы и объединения блоков.

Все автоматические тесты проекта проходят после изменений.


## v0.3.9 — разделение групп по составу детей

Исправлена важная ошибка группового режима: раньше предварительная серия делилась в основном по паузе между файлами. Если фотограф быстро переходил к следующей группе, десятки разных групп могли попасть в один временной блок и анализироваться как одна серия.

Теперь внутри каждого временного блока выполняется отдельное разбиение по **смене состава распознанных детей**. Для решения о границе используется только identity embedding InsightFace; положение ребёнка в кадре не считается доказательством совпадения группы. Потенциальная новая группа должна быть подтверждена следующим кадром, поэтому одиночный плохой embedding не создаёт ложную границу.

Повторное объединение через длинную паузу стало консервативнее: требуется устойчивое совпадение большей части identity на нескольких граничных кадрах, а не один наиболее удачный pair.

В итоговой статистике добавлено `Найдено границ по смене состава детей`.

## v0.3.8 — portable-функционал удалён

Встроенной portable-сборки больше нет: удалены PyInstaller builder, portable self-test, вопрос в `install.bat`, fallback на portable из `run.bat` и связанные тесты. Это упрощает установку и поддержку.

### Перенос на другой компьютер

`runtime\venv` **не считается переносимым окружением**. Python официально рекомендует virtual environment удалять и пересоздавать в целевом месте, а не копировать как готовый runtime. Поэтому надёжный перенос выглядит так:

```text
1. Скопировать всю папку Photo Select AI на другой Windows-компьютер.
2. Запустить там install.bat.
3. Установщик создаст/проверит локальный runtime\venv, CUDA runtime и InsightFace-модели.
4. После этого использовать run.bat.
```

Сам проект, конфигурацию и модели можно копировать. Если вместе с папкой приехал старый `runtime\venv`, не следует полагаться на него как на переносимый Python; при проблемах его лучше удалить и заново запустить `install.bat`.

## Главное изменение v0.3.5 — независимые правила Portrait / Group

Портретный алгоритм и его профили **не изменены**. Group mode теперь хранит и применяет собственный профиль правил независимо от портретного режима. Переключение режима не перезаписывает веса портрета.

Рекомендуемый групповой профиль — **«Глаза прежде всего»**:

- количество детей с уверенно открытыми глазами — первичный критерий выбора RED;
- остальные критерии используются после сравнения глаз;
- если есть ребёнок с закрытыми глазами, целевой YELLOW ищется только для того же identity с открытыми глазами;
- по умолчанию `YELLOW минимум = 1`, поэтому даже без формального дефекта сохраняется один сильный резервный дубль;
- `YELLOW максимум = 3`.

Дополнительные групповые профили: **«Сбалансированный»** и **«Больше резервных кадров»**. Эти правила не влияют на Portrait.

## Главное изменение v0.3.4 — YELLOW по конкретному ребёнку и открытым глазам

В групповом режиме закрытые/прикрытые глаза теперь являются отдельной проблемой и не скрываются средним quality score лица. Если на RED у ребёнка глаза закрыты, YELLOW-кандидат ищется только среди кадров **того же identity-track**, где глаза действительно открыты. Кадр с тем же ребёнком, но всё ещё прикрытыми глазами, не считается решением.

Главный RED также получил отдельный штраф за количество детей с закрытыми глазами, поэтому при прочих равных выбирается дубль, где больше детей смотрят с открытыми глазами. В журнал добавлена диагностика: проблемы глаз/отсутствия лица/резкости/качества, сколько проблем закрыто YELLOW и сколько осталось без подходящего дубля.

## Главное изменение v0.3.3 — полный прогресс и без итогового popup

В групповом режиме шкала прогресса теперь отражает не только CUDA-анализ фотографий, но и дальнейшую обработку: поиск групповых серий, объединение частей одной физической группы, сопоставление детей, построение треков, оценку покрытия, выбор RED/YELLOW и запись XMP. 100% появляется только после полного завершения обработки.

## Алгоритм серий (ядро v0.2.5)

После перехода на InsightFace детекция лиц стала заметно стабильнее, но на реальной съёмке проявились две другие проблемы:

- один ребёнок иногда разбивался на 2–3 соседние серии и получал несколько RED;
- одиночная ложная детекция на стене, полу, зеркале или случайном кадре могла превратиться в отдельную серию.

Логика серий двухступенчатая:

```text
файлы по времени/имени
        ↓
InsightFace SCRFD + ArcFace embedding
        ↓
строгий DBSCAN (по умолчанию distance 0.27)
        ↓
объединение только соседних фрагментов
того же ребёнка (по умолчанию distance 0.32)
        ↓
проверка доказательств серии:
минимум 2 уверенных обнаружения лица
        ↓
объединение того же ребёнка через короткую паузу
между соседними временными блоками
        ↓
1 RED на итоговую серию
```

Это гистерезис: строгий порог отвечает за разделение похожих детей, а немного более мягкий применяется **только к соседним уже найденным фрагментам**. Поэтому для уменьшения дублей больше не требуется просто повышать DBSCAN distance для всей съёмки.

Правило из исходного ТЗ сохраняется:

```text
ребёнок A → ребёнок B → ребёнок A
```

остаётся тремя отдельными сериями. Объединение никогда не перепрыгивает через подтверждённую серию другого ребёнка.

## Защита от стены / пола / случайного кадра

SCRFD по-прежнему работает с мягким порогом (по умолчанию `0.25`), чтобы не потерять сложное лицо. Но **новая серия** должна отдельно получить подтверждение:

```text
Порог подтверждения лица:              0.45
Мин. уверенных кадров для новой серии: 2
Мин. площадь подтверждающего лица:     0.05 %
```

Поэтому единичный false positive детектора не становится серией. Для реальной съёмки, где типичная серия содержит 3–20 кадров, минимум 2 подтверждения является рекомендуемым значением.

Если у вас действительно бывают одиночные портреты, параметр можно установить в `1`.

## Повторные тесты и старые RED-метки

Предыдущие версии добавляли новые RED-метки, но не снимали результаты старых запусков. После нескольких тестов Adobe Bridge мог показывать одновременно выборы разных версий алгоритма.

В быстром старте есть:

```text
[✓] Перед анализом снять старые RED-метки
```

При включённой опции программа удаляет **только текущее имя RED label** (например `Select`) и затем выполняет новый анализ. Остальные XMP-поля, Camera Raw настройки и рейтинги сохраняются.

Если вы вручную используете ту же красную метку до запуска программы и не хотите её снимать — выключите параметр.

Для JPG сначала проверяется только заголовок JPEG; весь большой файл перечитывается и переписывается только когда старая целевая метка действительно найдена.

## InsightFace

Весь анализ лица построен на одном InsightFace model pack `buffalo_l`:

```text
SCRFD             → поиск лица
recognition model → embedding ребёнка
2d106det           → 106 landmarks глаз/рта
OpenCV/Numpy       → резкость лица/глаз и технические метрики
```

Старого MediaPipe backend в проекте больше нет.

## Расширенные → «Серии и лица»

У каждого числового параметра есть `ⓘ`/HelpTip: **минимум**, **максимум**, рекомендуемое значение и объяснение эффекта увеличения/уменьшения.

### DBSCAN distance

- диапазон: `0.10–0.60`;
- рекомендуется: `0.25–0.30`;
- по умолчанию: `0.27`.

Это **строгий первичный** порог. Не рекомендуется повышать его только ради устранения дублей одного ребёнка — для этого теперь есть отдельный параметр объединения соседних фрагментов.

### Дистанция объединения соседних фрагментов

- диапазон: `0.20–0.50`;
- рекомендуется: `0.30–0.34`;
- по умолчанию: `0.32`.

Больше → лучше соединяет профиль/анфас одного ребёнка, которые DBSCAN разделил.

Слишком большое значение → может объединить двух очень похожих детей, поэтому этот порог применяется только к соседним фрагментам.

### Мин. уверенных кадров для новой серии

- диапазон: `1–6`;
- рекомендуется: `2`;
- по умолчанию: `2`.

Главный регулятор ложных серий. Если случайные стены/зеркала всё ещё появляются — сначала увеличьте этот параметр до `3`.

### Порог подтверждения лица

- диапазон: `0.20–0.90`;
- рекомендуется: `0.40–0.55`;
- по умолчанию: `0.45`.

Это не SCRFD detection threshold. Низкий SCRFD threshold нужен для полноты поиска, а этот более высокий порог решает, достаточно ли надёжно лицо для **создания новой серии**.

### Допуск кадров без embedding

- диапазон: `0–8`;
- рекомендуется: `2–4`;
- по умолчанию: `3`.

Пропущенный/смазанный кадр внутри уже подтверждённого ребёнка не разрывает серию, если тот же ребёнок распознан с обеих сторон.

Кадры без лица в начале или конце блока теперь не присоединяются к ребёнку автоматически.

### Объединять того же ребёнка через паузу

- диапазон: `0–180 с`;
- рекомендуется: `30–60 с`;
- по умолчанию: `45 с`.

Если длинная пауза или скачок номера файла разорвали съёмку одного ребёнка на два грубых временных блока, два **соседних** блока могут быть объединены обратно по ArcFace embedding.

`0` отключает этот механизм.

### Дистанция объединения через паузу

- диапазон: `0.15–0.45`;
- рекомендуется: `0.27–0.31`;
- по умолчанию: `0.30`.

Если один ребёнок по-прежнему выбирается дважды именно после паузы, слегка увеличивайте этот параметр. Если склеиваются два похожих ребёнка — уменьшайте.

```text
Допуск без embedding:                    3

Макс. пауза грубого блока:              12 сек
Объединять того же ребёнка через паузу: 45 сек
Дистанция объединения через паузу:       0.30
Мин. кадров итоговой серии:              2

SCRFD threshold:                         0.25
Detector size:                           640
```

Если **один ребёнок выбирается несколько раз**:

1. сначала `Дистанция соседнего объединения 0.32 → 0.34`;
2. если дубль возникает после длинной паузы — `Дистанция через паузу 0.30 → 0.32`;
3. DBSCAN `0.27` менять только после этого.

Если появляются **случайные серии**:

1. `Мин. уверенных кадров 2 → 3`;
2. затем `Порог подтверждения 0.45 → 0.50`;
3. только затем повышать основной SCRFD threshold.

Так полнота обнаружения детей страдает меньше.

## Вкладка «Критерии выбора»

Каждый критерий имеет независимый вес `0.00–3.00`. Вес `0` полностью исключает критерий.

По умолчанию:

```text
Открытые глаза — обязательный фильтр: ВКЛ
Порог открытых глаз:                  0.52
Вес открытых глаз:                    1.80
Штраф закрытых глаз:                  0.45
Вес резкости глаз:                    1.40
Вес резкости лица:                    0.90
Вес выражения лица:                   0.70
Вес улыбки:                           0.35
Вес технического качества:           0.35
```

## CUDA / RTX 5090

Рекомендуемый режим:

```text
InsightFace provider: auto
cuDNN Conv:           HEURISTIC
```

Сборка использует ONNX Runtime GPU 1.26.0 и ветку CUDA 12.8/cuDNN 9.24. Установщик после установки прогоняет detector, recognition и landmarks на CUDA.

Если включена защитная опция CUDA → CPU и реальный CUDA runtime падает, весь InsightFace пересоздаётся один раз на CPU и текущий кадр повторяется; кадр не пропускается.

## Установка

1. Распакуйте архив поверх предыдущей версии или в новую папку.
2. Запустите `install.bat`.
3. При HTTPS-перехвате Kaspersky можно выбрать `2 — Kaspersky compatibility mode`.
4. После установки окно ждёт нажатия клавиши и не закрывается автоматически.
5. Запустите `run.bat`.

Можно передать каталог сразу:

```bat
run.bat "D:\Photos\Shoot"
```

CLI:

```bat
run.bat "D:\Photos\Shoot" --cli
```

## Итоговая статистика

В итоговой статистике дополнительно показываются:

```text
Серий после распознавания лиц
Объединено соседних фрагментов
Объединено серий через паузу
Отброшено слабых/случайных серий
Старых RED-меток снято перед запуском
Обработано портретных серий
Выбрано лучших портретов
```

Эти числа нужны для дальнейшей калибровки на реальной школьной съёмке.
